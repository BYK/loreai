Storage is only one part of the workflow.

Lore records history, distills older working context, and curates project knowledge. What reaches a request is selected within scope and context limits. Your agent can use recall to look up details beyond that material.

Understand stored history and current context →

Know the extra work before a long session.

Distillation, curation, and conversation imports can make model calls. Provider pricing, model choices, and configuration affect their cost. Inspect recorded estimates in the local app and compare them with your provider’s actual usage.

On your machine

SQLite stores conversations and memory. The project’s .lore.md contains reviewable knowledge you can share through Git.

Configured providers

Agent requests and background distillation, curation and imports can make model calls. Embeddings are local by default; a local failure falls back to keyword search. Hosted embeddings require explicit provider configuration.

Operational telemetry: privacy-filtered metadata is enabled in production builds. Read the data guide for the opt-out and provider boundaries.

Three ways of keeping and sharing memory.

Local Lore · Available now
Recorded sessions, context management, recall, and curated project knowledge through supported clients.
Git-based sharing · Available now
Commit and review .lore.md. It shares the knowledge file, not the full conversation database.
Folk Lore · Early access
The upcoming hosted team experience for continuous sharing. Joining the list expresses interest; it does not enable sync.

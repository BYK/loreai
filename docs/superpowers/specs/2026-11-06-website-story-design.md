# Website field guide and product story

The website shares the local app’s olive surfaces, DM Sans typography, amber actions and compact controls. The floating navigation and illustrated RPG journal are the approved visual direction.

## First-use journey

Lead with a concrete project-memory outcome. The headline preview highlights what a conversation contributes to the next session in green. Follow it with an explicitly fictional interactive journal, then a compact actual-app capture linking to the complete product tour.

The journal follows Conversation → Saved knowledge → Next session. Keep the larger inventory optional, preserve source inspection and explain why a rule matches the selected task. Unrelated knowledge remains stored. Native radio controls work without JavaScript; enhancement preserves allowlisted URL state, history, fragments and early native choices.

Setup follows Choose client → Install/connect → Verify recording, with six supported client choices, explicit CLI/Desktop distinctions, real commands and observable outcomes. The site does not claim a live connection or guarantee immediate knowledge extraction.

## Shared design and access

Use the floating field guide across public pages, articles and Starlight docs. Mobile navigation retains the logo mark and contains appearance controls. Keep icon buttons named, focus visible, touch targets generous and motion optional. Preserve 320px containment, keyboard access and native disclosure fallbacks.

Eight local Quiver illustrations each have geometry-identical light and dark palettes. Artwork explains the journal, decisions, conventions, lessons, storage, configured providers, carried knowledge and setup. No unused illustrations, 3D renderer or WebGL dependency ship.

Actual-app screenshots use coherent fictional fixtures. Source limitations remain explicit. Diagrams open in centered native dialogs with an accessible close icon, backdrop dismissal, Escape and focus restoration. Reference settings retain exact shareable field anchors and generated-source parity. Search works at root and prefixed preview paths.

## Product boundaries

Distinguish stored conversation, distilled context, durable knowledge and context supplied to a request. Explain local/provider/telemetry boundaries, opt-out and estimated-versus-billed costs. Local embedding failures degrade to keyword search; hosted embeddings require an explicit provider and API key. Distinguish local/Git features from Folk Lore early access.

No backend behavior, account requirements, release versions or changelog entries change. Superseded design iterations remain in Git history.

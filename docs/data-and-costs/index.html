Use Lore

Data and costs

Local storage and model processing are different boundaries. A local database does not make requests to a configured remote model provider stay on your machine.

Where information goes

Section titled “Where information goes”

On your machine

SQLite stores conversations and memory. The project’s .lore.md contains reviewable knowledge you can share through Git.

Configured providers

Agent requests and background distillation, curation and imports can make model calls. Embeddings are local by default; a local failure falls back to keyword search. Hosted embeddings require explicit provider configuration.

Operational telemetry: privacy-filtered metadata is enabled in production builds. Set SENTRY_ENABLED=0 before starting Lore to opt out.

Git-based sharing exports curated knowledge, not the complete conversation database. Folk Lore’s hosted team experience is early access; joining its list does not enable sync.

Telemetry choice

Section titled “Telemetry choice”

To opt out, set this before starting Lore:

Automatic telemetry excludes prompts and response bodies. Read the complete collected fields and exclusions for the precise boundary; this opt-out does not change what your configured model providers receive.

What can incur model charges?

Section titled “What can incur model charges?”

Your normal agent requests use its configured provider. Background distillation, curation, and conversation imports can make additional model calls. Models, conversation size, configuration, and provider terms affect cost. Lower spending is not guaranteed for every workload.

Preview an import before processing it:

The dry run inspects sources without curator model calls. Review its output and the import guide before proceeding with a large history.

Inspect usage

Section titled “Inspect usage”
  • Providers & costs shows available recorded spend estimates, background-work costs, and provider quota information when observed.
  • Model usage counts distinct recorded sessions per model and UTC day. It does not measure billed dollars or establish model switches within a conversation.
  • Provider bills and account consoles remain the source for actual charges.

Review worker model configuration and knowledge injection behavior when tuning. The .lore.json budget setting allocates context space, not a dollar spending cap.

Undo or remove Lore

Section titled “Undo or remove Lore”

Setup undo restores applicable routing settings. Uninstall explains what is removed and what memory is preserved. Deleting an active knowledge entry is not the same as purging conversation history or removing copies already committed to Git.

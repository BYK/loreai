Use Lore

Try a project-memory workflow

Use a disposable project to see the workflow. This example illustrates a useful result; it is not a benchmark or a guarantee about when extraction will run. Verify your connection first.

Record a decision

Section titled “Record a decision”

Tell your connected coding agent:

This webhook provider can deliver the same event twice. Check the event ID before applying an update. Reuse the shared duplicate check. Also, let’s get lunch at noon.

Continue normal work on the example. In the local browser, confirm the conversation appears under Sessions. That is the first observable result.

Review what becomes knowledge

Section titled “Review what becomes knowledge”

When curation produces an entry, open Knowledge and inspect Source & history. A useful entry would capture the duplicate-delivery rule, without turning the lunch plan into a durable project convention. Correct inaccurate wording before sharing it.

This is an illustrative diff excerpt. Real .lore.md entries include identity markers and categories; retain those when editing. Do not create a fake generated file just to make the demonstration pass.

Use it in a later task

Section titled “Use it in a later task”

Start another connected session in the same project and ask:

Add retries to the webhook handler. Look up our previous duplicate-delivery decision first.

Inspect the agent’s answer, recall results, and resulting code. Does it reuse the event-ID check? Does it cite or recover the original reasoning? The unrelated lunch plan should not drive this implementation. Check the actual behavior rather than assuming a recorded memory was supplied or followed.

A reproducible engine check

Section titled “A reproducible engine check”

The repository includes packages/core/test/website-workflow-evidence.test.ts. From a development checkout with dependencies installed, run:

This controlled check uses an isolated test database and two different session IDs:

StageInput or actionObserved result
First sessionRecord the webhook decision and a temporary port in a conversationThe original conversation remains retrievable.
Human reviewCreate the rule, then correct its incomplete wording to include reusing the duplicate-event guardVersion history retains both the initial text and the corrected current revision.
Later sessionSearch for webhook duplicate event guard within the same projectRecall returns the corrected rule and the earlier conversation. The temporary port is absent from the knowledge entry.

The check passed on 16 November 2026. It calls the real storage, versioning and recall functions; knowledge is deliberately created and corrected through the API, and embeddings are disabled. It does not run LLM curation, connect a coding client, measure savings, or establish that an agent follows the rule in generated code. Those remain separate observations in the hands-on workflow above.

What this proves

Section titled “What this proves”

A recorded conversation, a reviewable knowledge entry, and successful retrieval are separate observations. This small workflow helps you inspect those stages; it does not establish a general accuracy or cost improvement.

Read the historical evaluation and its limitations or learn to review and correct knowledge.

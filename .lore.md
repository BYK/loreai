## Long-term Knowledge

### Architecture

<!-- lore:01a08126-4de0-7a17-acbb-36db061a13de -->
* **#1711 Responses ingress boundary**: Chose streaming only \`/v1/responses\` and \`/v1/codex/responses\` over converting every JSON ingress route, because their shared OpenAI item normalizer can process \`input\` incrementally. Anthropic, Chat, Gemini, and compaction routes require distinct full-protocol parsing or intentionally retain exact body text for fallback replay. This reduces compressed/decoded/raw-tree peak allocations, but deliberately does not solve #1710’s post-parse full-history semantic replay: normalized \`GatewayRequest.messages\` are still complete.

<!-- lore:01a08daf-ae7e-72a6-89bb-2c59d44753ab -->
* **Assistant tool\_result exclusion**: Assistant responses must never contain \`tool\_result\`; tool results belong to user-side request/replay messages. Treating translated provider blocks uniformly looks simpler, but emits an invalid role/content pairing and can break downstream protocol consumers.

<!-- lore:01a08ccd-212f-77d1-a448-f1c3ceb8f73c -->
* **Billing header system\[0]**: The authoritative billing header is always \`req.system\[0]\`: Claude Code emits it there and the worker prepends it. Chose positional authority over content searching because copied billing-header text can appear elsewhere, but a copy can never occupy offset zero; scanning content risks treating user-controlled duplicates as authoritative.

Preserve full canonical \`k:\`/\`xk:\` IDs because \`recallById\` uses exact \`ltm.get(id)\` lookup; shortened IDs look cleaner but cannot resolve. Never suggest tombstoned entries for recall, because removed knowledge must not be surfaced as available context. Every revision of the Lore framing note starts with the bracketed \`Lore\` leading substring.

Track every connection until its \`close\` event; keep closure bounded and idempotent.

Moving deltas forward, caching passthrough, or independently rendering cache and pin text destabilizes cached bytes and can cause prefix drift or cache spirals.

### Pattern

<!-- lore:01a03e44-1d13-7a8f-ac02-97f6be0fa251 -->
* **jj-create-pr exact-change workflow**: Steps: 1. Resolve the intended stable change ID, defaulting to \`@-\` only after proving it has a nonempty diff and no trunk bookmark. 2. Inspect \`jj diff -r \<change>\` and derive a conventional title from its description. 3. Rebase onto current upstream, then verify \`jj st\`, \`jj log\`, conflicts, and the exact file scope—jj records conflicts without failing. 4. Create or identify the change’s bookmark and push only that bookmark; stop on push or branch-detection failure. 5. Open the PR against \`gh repo view\`’s default branch with assignee \`@me\`, \`## Summary\`, and 3–5 impact-focused \`## Changes\` bullets. 6. Run required validation and correctness/security review on the exact pushed head; address failures before merge. Gotchas: - An empty child above the patch makes \`@\` the wrong PR target; identify the parent explicitly. - Rebasing rewrites commit hashes but preserves stable change IDs. Verify: - \[ ] PR diff contains only the intended change. - \[ ] CI and required reviews pass on the final head.

<!-- lore:019f1cc8-b65e-7a6e-97ae-f48d1a7d542b -->
* **Recall execution, admission, and frozen-baseline invariants**: Consume synchronous \`recall\` results in the same turn; invoking recall as the final action creates a false search loop. Chose liveness-only admission over execution, token, item, result-byte, or retained-coverage quotas because productive chains may keep finding distinct sources; only the foreground deadline (with final-synthesis reserve) or proven consecutive no-progress coverage forces finalization. A bounded coverage ledger may evict keys, but evicted keys become unknown/progress rather than evidence of a stall. Offloaded frozen-baseline builders fall back to synchronous scan on \`READ\_JOB\_TIMED\_OUT\`, never \`\[]\`; \`forSession\` may return \`\[]\` because it reruns each turn.

<!-- lore:01a01eab-4463-721b-a380-46df306f3290 -->
* **shutdownVectorPoolAsync deadline**: Steps: 1. Snapshot workers, set \`shuttingDown=true\`, and reject in-flight requests — dispatch must stop first. 2. Post \`{type:"shutdown"}\` and await each exit — workers close reader connections cooperatively. 3. Race exits against an unrefed termination timer; treat \`postMessage\` failure as completion. 4. Make \`finish()\` idempotent, clear its timer, and always resolve. Gotchas: - A later \`const killTimer\` looks tidy, but an early throw invokes \`finish()\` in the TDZ; declare \`let\` first. - Immediate termination looks sufficient, but live reader WAL read-marks can prevent the writer’s TRUNCATE checkpoint and strand \`-wal\`; graceful gateway shutdown requires \`shutdownVectorPoolAsync()\`, not \`shutdownVectorPool()\`. Verify: - \[ ] Empty, repeated, and concurrent shutdowns resolve. - \[ ] Cooperative exit, forced deadline, and throwing \`postMessage\` resolve. - \[ ] Writer close occurs only after reader shutdown.

<!-- lore:01a06e0c-19f4-774b-94d2-219ee0714ed4 -->
* **Vitest exhaustive sharding**: Steps: 1. Run the normal full suite first — preserves the standard gate \[\[01a03e22-93bd-721c-ae79-e5484d4c6a5a]]. 2. If aggregate runtime or teardown obscures the result, confirm no test workers survived. 3. Partition every configured test file deterministically and run all shards with the repository’s 300s test timeout, \`hanging-process\`, and \`--printConsoleTrace\`. 4. Aggregate results and prove each included file ran exactly once. Gotchas: - Quoted globs look shell-safe, but Vitest treats them as literal filters and reports no files; use directories or explicit file lists. - A 30s diagnostic timeout looks bounded, but valid pipeline tests can need about 35s; retain the repository timeout. Verify: - \[ ] Every configured test file belongs to one shard. - \[ ] Every shard exits cleanly. - \[ ] The changed test file also exits cleanly under handle diagnostics.

### Preference

<!-- lore:01a08fd4-1dc7-7d88-ae13-c8f96c97a5a1 -->
* **Always enforce recall safety invariants with regression tests**: Treat recall-chain behavior as governed by strict, testable invariants. Prevent recall dispatch when the principal/continuation is invalid, incomplete, over budget, or final; ensure final continuations cannot recurse. Preserve lifecycle and public-error contracts: recall-only failures remain failures, diagnostics and internal details do not alter or leak through the fixed public recall failure, and tool calls/events are absent when recall is blocked. Avoid arbitrary execution/result-size limits and do not infer stalled progress from missing legacy coverage. Keep ordinary request builders from forwarding recall-specific control/cache fields. Add or maintain precise regression coverage for these constrained paths, including call counts, SSE terminal-event counts, sanitized output, usage, and callback results.

<!-- lore:01a08fe3-b4d2-71de-9718-1f2380e1448b -->
* **Always keep recall source coverage private**: Treat \`onRecall\`/recall-result \`coverage\` as internal source-coverage metadata only. Preserve and use it for server-side recall budgeting, diagnostics, and related internal accounting where applicable, but never include it in client-visible Responses/SSE events, output items, serialized response payloads, or follow-up text. When modifying \`streamResponsesRecallAware\` or its callback contracts, retain explicit documentation and behavior that coverage is never emitted to the client.

<!-- lore:01a08fd4-ae21-7ab4-9313-86e1d40a09fe -->
* **Always normalize OpenAI upstream authentication to Bearer**: For OpenAI-protocol upstream request builders, preserve and forward the credential value extracted from the incoming request, but always rewrite its authorization scheme to \`Bearer\`. Do not preserve or infer the incoming scheme (such as Basic or a custom scheme). Implement the managed Authorization header as \`Bearer ${cred.value}\`, overriding any forwarded client Authorization header.

<!-- lore:01a08ff8-3bc0-7711-98d5-393593c0fe17 -->
* **Always preserve explicit pipeline safety invariants**: Treat documented “never” contracts as hard requirements during gateway changes. Keep recall follow-up request construction, forwarding, content-type validation, and parsing coupled so the \`stream\` flag can never diverge from how the continuation is consumed; use the established streaming or JSON follow-up helpers rather than manually pairing these steps. Also ensure ancillary diagnostics, completion telemetry, and lore context-warning banner logic never throw, block, or alter the response/read path. Verify these invariants when modifying recall continuation, retry, rollback, terminal delivery, or completion handling.

<!-- lore:01a08fee-593d-7a43-8289-30b7e2583ba9 -->
* **Always preserve explicit upstream protocol invariants**: When working on gateway translation or forwarding code, treat the user’s stated protocol rules and code comments as non-negotiable invariants. Implement and verify exact behavior rather than inferring from incoming client conventions or generic provider defaults—for example, normalize OpenAI-protocol credentials to Bearer, keep cache thresholds consistent with the actual quantized anchor calculation, and preserve documented stateless/provider-specific routing behavior. Account for edge cases explicitly, especially where a configuration or threshold would otherwise silently claim behavior that cannot occur.

<!-- lore:01a08fea-69ed-71f9-8fcc-bab5d605a147 -->
* **Always prove bug fixes with failing-first regression tests**: For every defect fix, first add a deterministic regression that reproduces the real precondition and confirm it fails on the base branch. Then confirm the same test passes with the fix and would fail again if the relevant guard were removed. Do not accept passing-only tests or trust implementation reasoning without observed base failure. For non-trivial changes, freeze and hash the candidate, run the full test/typecheck/lint/format gates plus required repeated property tests, and obtain separate adversarial correctness and security reviews with file:line evidence and explicit verdicts before merging or opening the PR.

<!-- lore:01a03426-3ac8-7efa-a762-ebc817c120a7 -->
* **Cache-stable prompt deltas and pinned knowledge placement**: Keep cached system-prefix and pinned/distilled knowledge byte-identical, ordered, and in designated prefix positions whenever selected knowledge is unchanged. Store LTM separately in its cacheable system block and use the established one-hour TTL. Place durable prompt deltas near the message tail, never in the cached prefix or between tool\_use and matching tool\_result. Compute and persist tool-pair-safe positions, reuse them for cache stability, and re-anchor only after layout changes such as compression or cache warming. Apply deltas after orphan safety processing and safely degrade rather than emit invalid tool sequences. Derive cache and pin representations from the same baseline so restarts do not drift.

<!-- lore:01a04a84-4cb4-7c88-ad20-4301bfc48ca6 -->
* **cmdEnable cancellation disables sync**: Always disable sync when encryption setup is canceled, even when sync was already enabled. Preserving the previous state looks conservative, but it can keep pushing plaintext after encryption becomes mandatory; cancellation must perform no sync and require an explicit re-enable with a passphrase.

<!-- lore:01a01a58-ecaf-7824-8a8f-0d8210016aa5 -->
* **Craft version CHANGELOG ownership**: Never manually bump versions or edit CHANGELOG; Sentry Craft owns release versioning and changelog generation for BYK/loreai releases via GitHub Actions. Manual edits look harmless locally but conflict with Craft's generated release state and can be overwritten or produce inconsistent artifacts.

<!-- lore:01a039c5-3b2a-7098-8a9b-167eb13d8737 -->
* **Durable logging and always-visible coverage diagnostics**: Errors must always reach persistent file logging and registered LogSink consumers after credential redaction. Embedded TUI mode may silence stderr process-wide, but must not suppress file or sink delivery. Startup embedding-coverage failures also require an always-visible reviewed stderr path: log.info() is insufficient because it reaches stderr only with LORE\_DEBUG=1. Preserve embedded/TUI stderr-silencing behavior while ensuring coverage failures remain visible in ordinary non-debug operation.

<!-- lore:01a03ceb-4c03-7d8c-b142-8a82e2395dbd -->
* **embedding startup reconciliation order**: Always run provider-independent \`checkConfigChange()\` before the provider-availability return and before \`maybeCutoverToVec0()\`; otherwise unavailable embeddings can skip physical vec0 repair, while reversing cutover order can seed vec0 from stale blobs.

* **@loreai/pi compaction: extension hook + /v1/compact endpoint integration**: Pi's compaction goes through its extension API (\`pi.on('session\_before\_compact', ...)\`), not HTTP, so the gateway's usual HTTP-interception (pattern-matching Claude-Code-style requests) doesn't apply. Instead the hook calls the gateway's \`POST /v1/compact\` endpoint directly for a full LLM-synthesized summary (force-distill + knowledge + compact prompt), passing gatewayBase, sessionID, projectPath, previousSummary, firstKeptEntryId, tokensBefore from Pi's \`event.preparation\`. \`runCompaction()\` never throws and never writes to stdout/stderr (same TUI-safety pattern as elsewhere) — outcomes are: 404 \`session\_not\_found\` (session never routed through Lore, falls back to Pi's native compaction), thrown/network error (same fallback), or success returning \`{compaction: {summary, firstKeptEntryId, tokensBefore}}\`. Pi's native compaction (session-manager.ts) triggers when \`contextTokens > contextWindow - reserveTokens\` (default reserveTokens=16384), keeps \`keepRecentTokens\` (default 20000), and hard rule: never cuts at tool results (they must stay with their tool call). * **readStorageMode / setStorageMode: monotonic latch and consistency**: Design principles for vector storage mode abstraction: (1) monotonic latch: once vec0 mode is observed, it NEVER falls back to blob mode — base embedding columns dropped after mode flip ensures no dropped-column reads. (2) setStorageMode consistency: the sticky read latch must agree with what was just written, preventing checkpoint/time-travel disagreements. (3) Callers must never reason about the 2×2 matrix (blob, blob-native, vec0, write-order) — the abstraction hides implementation details. (4) Safe fallback (unrecognized table\_type) must never assume vec0. (5) Resetting the storage mode latch ensures a fresh blob DB is never poisoned by a prior vec0 observation.

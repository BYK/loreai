* **sync.ts pushEntry: phantom columns on knowledge\_entity\_refs cause permanent push stall**: Trap: \`pushEntry\` unconditionally adds \`content\_hash\`, \`revision\`, \`is\_deleted: false\` to ALL tables including \`knowledge\_entity\_refs\`. <!-- lore:019ece19-d8f2-7d7b-8b78-969756c830ae -->
* **sync.ts pushOnce: minCursor=0 from empty-table cursors blocks pruneOutbox forever**: Trap: \`pushOnce\` computes \`minCursor = Math.min(...per-table push cursors)\`. A synced table with zero outbox entries keeps cursor \`0\`. \`pruneOutbox(minCursor)\` early-returns when \`minCursor <= 0\` → outbox NEVER pruned whenever any one synced table has zero pending entries. Fix: compute \`minCursor\` only over tables where \`hasOutboxEntries()\` is true — empty tables excluded from floor calculation. Push-prune race is benign: rows inserted after cursors are read get \`seq > minCursor\` (AUTOINCREMENT monotonicity) → always survive prune.

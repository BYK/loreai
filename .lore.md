* **4 LTM injection channels: system\[1] baseline, system\[2] REMOVED, knowledge delta, recall tool**: Lore has 4 knowledge injection channels: (1) system\[1] baseline — \`buildLoreContextCapabilityNote(sessionToken)\` with preferences + entities + ToC, cached ≥1h (pipeline.ts:7839), always present from turn 1, byte-stable; (2) system\[2] full injection — REMOVED Jul 27 2026 (issue #1502 fix): \`ltmSystem\` field deleted, \`ltmText\` always undefined, \`contextTokens\` simplified to just stable token count, \`ltmParts\` reduced to \`\[cache?.stableLtmSystem].filter(Boolean)\`; (3) knowledge delta — durably appended user→assistant pair mid-session; (4) recall tool result. * **readStorageMode / setStorageMode: monotonic latch and consistency**: Design principles for vector storage mode abstraction: (1) monotonic latch: once vec0 mode is observed, it NEVER falls back to blob mode — base embedding columns dropped after mode flip ensures no dropped-column reads. (2) setStorageMode consistency: the sticky read latch must agree with what was just written, preventing checkpoint/time-travel disagreements. (3) Callers must never reason about the 2×2 matrix (blob, blob-native, vec0, write-order) — the abstraction hides implementation details. (4) Safe fallback (unrecognized table\_type) must never assume vec0. (5) Resetting the storage mode latch ensures a fresh blob DB is never poisoned by a prior vec0 observation.

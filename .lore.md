* **Embedding pipeline: scheduling, workers, chunk storage, GC**: Embedding scheduling, validation, ranking, and vector GC: Backfills measure byte length with length(CAST(content AS BLOB)) because SQLite TEXT length stops at NUL. ### Gotcha

<!-- lore:01a11b9b-19f0-777e-8c8a-08d76f25a670 -->
* **aggregateTokensBySession detail metadata**: Trap: excluding \`recall\_only\` rows from token sums looks like a complete session-rollup fix, but an earliest-assistant metadata query can still select a detail-only row, even at a tied timestamp; an all-detail session can then appear with zero tokens. Fix: exclude detail-only rows in both the inner earliest-assistant selection and outer joined selection of \`aggregateTokensBySession()\` and \`aggregateTokensBySessionAll()\`.

<!-- lore:01a0f507-a186-7f5c-956f-ffb38895adb4 -->
* **allowRemoteManagement token bypass**: Trap: \`allowRemoteManagement\` plus socket-peer and Origin checks looks like remote access control, but non-browser clients can omit Origin; the gateway-token check covers only data-plane routes. With remote management enabled, an unauthenticated non-loopback client can reach \`/api/\*\` mutations. Authenticate remote management before routing; test a no-Origin remote mutation without credentials (denied) and with valid credentials (accepted). When reviewing, distinguish this pre-existing gap from candidate-introduced defects without treating a warning or default-disabled setting as authentication.

<!-- lore:01a11db1-03b1-747c-839e-fe87dbf69b07 -->
* **Anthropic meta-request caching**: Trap: enabling conversation caching for title and summary passthrough looks consistent with normal Anthropic turns, but meta-request content changes each call, causing cache writes at 1.25× cost with no useful reads. Fix: never enable caching for meta-request passthrough; keep stable-prefix caching for normal conversations separate.

<!-- lore:01a0f672-2bdd-72c7-9df7-1fc95f1fa9a2 -->
* **backupDatabase live-path collision**: Use a consistent \`VACUUM INTO\` snapshot, not a copy of the live SQLite file, which may omit WAL contents. Reject any existing backup destination, including a dangling symlink (check with \`lstatSync\`), and any destination overlapping the live database, \`-wal\`, or \`-shm\` path. Preserve existing targets and sidecars byte-for-byte; never delete the live database to recover from a backup mistake.

<!-- lore:01a121a4-5066-790e-87b0-af8eeb7b93ac -->
* **buildKnowledgeDeltaMessage Unicode title truncation**: Trap: slicing an overflow title to 122 UTF-16 code units before \`Array.from()\` looks like a cheap bound, but can split an astral character and persist a lone surrogate in the recall index. Convert to code points first, then take 120: \`Array.from(e.title).slice(0, 120).join("")\`. Test the persisted delta with an astral character at the cutoff.

<!-- lore:01a0fef9-c9e2-7e02-99d4-95c0aee20929 -->
* **CANONICAL\_MODEL\_PROVIDERS capability precedence**: Trap: letting the last models.dev provider entry win for a bare model ID looks like ordinary map construction, but aggregators can publish conflicting capability flags for first-party models. Fix: reapply canonical OpenAI and Anthropic entries after indexing all providers so first-party \`temperature\` and \`reasoning\_options\` win regardless of JSON order; keep provider-qualified entries for route-specific pricing.

<!-- lore:01a118fb-9459-7070-9433-532c7172da5c -->

Fix: for checkpoint admission, use only a valid current-session overhead EMA; otherwise use a first-turn reserve scaled so it cannot consume most of a small context window. A fixed 15,000-token reserve falsely rejected a fitting turn on a 27,000-token window.
